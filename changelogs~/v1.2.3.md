description: "Adds .sfd Data Assets: shared data tables with inheritance that dialogue graphs read and write, that gate options, that persist in saves and that game code reaches through a typed C# API. ##### New Features

- **.sfd Data Assets**: data tables authored in StoryFlow editor 1.7.0 or newer now import and execute in Unity. Every referenced `.sfd` and its full ancestor chain arrive as one ScriptableObject per asset under `Assets/StoryFlow/DataAssets`, named by asset id so a rename in the editor does not orphan scene references. Declaration order and authored map key order are preserved, and the imported table is used exactly as the editor shipped it: no re-validation, no dedup and no string table pass, so a `.sfd` string value stays the literal it was authored as
- **Three Data Asset nodes**: `Get Data Asset` is the reference pill, and `Get Data Asset Variable` and `Set Data Asset Variable` are the accessors wired to it. The wire is the binding: an accessor carries no asset of its own, so pointing its pill at a different asset repoints every accessor downstream of it. Both accessors read as typed values in condition and value chains, including arrays and maps, and the Set node passes its written value through so it can feed the rest of a chain
- **Inheritance and the session overlay**: a read walks the asset's parent chain from the referenced asset up to its root. Nearest wins, so a value set or overridden on an ancestor cascades to every descendant that does not shadow it, and the root-most declaration owns the slot regardless of which level carries the value. Writes are session state: they land at the referenced asset's own level and never touch the imported table, so setting through a child overrides for that child's subtree while setting through the base cascades. Reads and writes copy in and out, so graph code cannot reach into the store through a value it was handed
- **Option gating on Data Asset booleans**: a boolean `.sfd` variable read through an accessor gates a dialogue option like any other boolean producer, directly or through the boolean logic nodes. A write mid-dialogue drops the evaluation memos, so an option condition already evaluated above the accessor re-evaluates against the new value instead of answering with the old one
- **Data Assets in saves**: the session overlay persists under a new `dataAssets` key in the save state, sparse (only what the session wrote, never the imported table) and as bare values rather than typed records, which is the same shape the editor's own runtime writes. Load replaces rather than merges, so loading a save drops writes the save does not carry. A save with no such key, which includes every save written before this version, correctly restores the imported state. Values are typed on the way back in from the declaration that owns them, so an enum stays an enum and an empty array stays an array
- **Typed C# API for Data Assets**: `GetDataAssetBool`, `GetDataAssetInt`, `GetDataAssetFloat`, `GetDataAssetString`, `GetDataAssetEnum` and the matching `SetDataAsset*` setters take an asset reference and the variable name typed in the editor, resolved through the same chain the nodes walk. Getters report failure through an `out bool found` and setters through their return value, and the type gate is strict: no coercion, and enum is deliberately not reachable through the string pair (image, audio and character values are, since they travel as bare paths). `GetDataAssetVariant` is the untyped door, reading any variable including arrays and maps as a detached copy. Reads cover every type while writes cover scalars only, because rebuilding a whole container with the right element typing is the Set node's job and not something a caller should have to get right by hand
- **The same API on `StoryFlowManager` as on `StoryFlowComponent`**: Data Asset state is global to the game rather than owned by any one dialogue, so the whole typed surface is on the manager too. A shop, an inventory screen, a save menu or any other script with no dialogue of its own reads and writes it directly instead of hunting for a `StoryFlowComponent` to borrow. Both surfaces run the same lookup and the same type gate, so they cannot answer differently; the component's setters additionally refresh their own dialogue's cached conditions, which is the one thing a manager has no dialogue to do
- **Unified cross-engine save format**: `ExportState` and `ImportState` on `StoryFlowManager` read and write the state format shared with the other StoryFlow runtimes, and the slot API now writes the same document byte for byte. Loading never throws on malformed input and still accepts the legacy Unity dialect, so upgrading is safe. Downgrading is not: a save written by this version cannot be read by a plugin version predating the unification

##### Breaking Changes

- **`StoryFlowSaveHelpers.Save` and `SaveAsync` take two more arguments**: both now require the Data Asset seed and the session overlay after the existing three, so a saved slot carries `.sfd` session state like the string API does. Code calling them through `StoryFlowManager` (`SaveToSlot`, `ExportState` and the rest) is unaffected. Code calling the helpers directly needs the two extra arguments and should pass `null, null`, which writes an empty key and reads back as a save with no Data Asset state in it. To save a slot that does carry it, call `StoryFlowManager.SaveToSlot` instead, which supplies the pair from the live store

##### Bug Fixes

- **Fixed character names and images not surviving load**: the save wrote each character's name and image but the loader applied neither, so a story that renamed a character or swapped their portrait lost both changes on load while the other runtimes restored them. Both are restored now and merge leniently, so a character absent from the save keeps its current state and an absent name or image field keeps its current value. The image asset key is what is restored and the Sprite re-resolves on the next render, the same way it does after a `SetCharacterVar`

##### Improvements

- **Broken Data Asset bindings degrade instead of failing**: an accessor with nothing wired to its pill, an unbound pill, a pill pointing at an asset the build does not carry, a variable no level of the chain declares any more, or a variable whose type changed since the node was made all read the type default and warn once per node, and refuse the write on the Set side rather than putting a zero over an authored value. A Set node whose value input is unwired is refused as well, for the same reason. The warnings re-arm on the next dialogue start, which builds a fresh execution context, so a problem that is still there is reported again on the next run rather than staying silent for the life of the session
- **Data Asset API mistakes are reported once, not once per frame**: a getter or setter called with a name that no longer exists, or against the wrong type, still reports the refusal on every call through `found` or its return value, but only writes the first one to the console. A script polling a renamed variable from `Update` used to log a line per frame, which in the editor carries a stack trace each time and in a build grows `Player.log` without limit. Each distinct mistake still gets its own line, and loading a different project or resetting state re-arms them, so a name that has genuinely gone missing is reported again rather than staying silent
- **First sync after upgrading rewrites every asset once**: imported assets record a hash of the JSON they were built from and are skipped when it matches, but that hash described the source only, so upgrading the plugin (which changes how the source is parsed, not the source itself) skipped every asset and left them holding whatever the previous version made of them. On this version that would have meant every Data Asset node in an already imported project staying unrecognized until someone happened to edit the script it lives in. The recorded hash now includes an import parse version, so the first import or live sync after installing 1.2.3 writes every script, character, project and data asset once and records the new hashes, which under version control is one diff per asset. Unchanged media is compared by content and is not recopied. Every sync after that only touches what actually changed
