##### New Features

- **.sfd Data Assets**: data tables authored in StoryFlow editor 1.7.0 or newer now import and execute in Unity. Every referenced `.sfd` and its full ancestor chain arrive as one ScriptableObject per asset under `Assets/StoryFlow/DataAssets`, named by asset id so a rename in the editor does not orphan scene references. Declaration order and authored map key order are preserved, and the imported table is used exactly as the editor shipped it: no re-validation, no dedup and no string table pass, so a `.sfd` string value stays the literal it was authored as
- **Three Data Asset nodes**: `Get Data Asset` is the reference pill, and `Get Data Asset Variable` and `Set Data Asset Variable` are the accessors wired to it. The wire is the binding: an accessor carries no asset of its own, so pointing its pill at a different asset repoints every accessor downstream of it. Both accessors read as typed values in condition and value chains, including arrays and maps, and the Set node passes its written value through so it can feed the rest of a chain
- **Inheritance and the session overlay**: a read walks the asset's parent chain from the referenced asset up to its root. Nearest wins, so a value set or overridden on an ancestor cascades to every descendant that does not shadow it, and the root-most declaration owns the slot regardless of which level carries the value. Writes are session state: they land at the referenced asset's own level and never touch the imported table, so setting through a child overrides for that child's subtree while setting through the base cascades. Reads and writes copy in and out, so graph code cannot reach into the store through a value it was handed
- **Option gating on Data Asset booleans**: a boolean `.sfd` variable read through an accessor gates a dialogue option like any other boolean producer, directly or through the boolean logic nodes. A write mid-dialogue drops the evaluation memos, so an option condition already evaluated above the accessor re-evaluates against the new value instead of answering with the old one
- **Data Assets in saves**: the session overlay persists under a new `dataAssets` key in the save state, sparse (only what the session wrote, never the imported table) and as bare values rather than typed records, which is the same shape the editor's own runtime writes. Load replaces rather than merges, so loading a save drops writes the save does not carry. A save with no such key, which includes every save written before this version, correctly restores the imported state. Values are typed on the way back in from the declaration that owns them, so an enum stays an enum and an empty array stays an array
- **Typed C# API for Data Assets**: `GetDataAssetBool`, `GetDataAssetInt`, `GetDataAssetFloat`, `GetDataAssetString`, `GetDataAssetEnum` and the matching `SetDataAsset*` setters on `StoryFlowComponent` take an asset reference and the variable name typed in the editor, resolved through the same chain the nodes walk. Getters report failure through an `out bool found` and setters through their return value, and the type gate is strict: no coercion, and enum is deliberately not reachable through the string pair (image, audio and character values are, since they travel as bare paths). `GetDataAssetVariant` is the untyped door, reading any variable including arrays and maps as a detached copy. Reads cover every type while writes cover scalars only, because rebuilding a whole container with the right element typing is the Set node's job and not something a caller should have to get right by hand
- **Unified cross-engine save format**: `ExportState` and `ImportState` on `StoryFlowManager` read and write the state format shared with the other StoryFlow runtimes, and the slot API now writes the same document byte for byte. Loading never throws on malformed input and still accepts the legacy Unity dialect, so upgrading is safe. Downgrading is not: a save written by this version cannot be read by a plugin version predating the unification

##### Bug Fixes

- **Fixed character names and images not surviving load**: the save wrote each character's name and image but the loader applied neither, so a story that renamed a character or swapped their portrait lost both changes on load while the other runtimes restored them. Both are restored now and merge leniently, so a character absent from the save keeps its current state and an absent name or image field keeps its current value. The image asset key is what is restored and the Sprite re-resolves on the next render, the same way it does after a `SetCharacterVar`

##### Improvements

- **Broken Data Asset bindings degrade instead of failing**: an accessor with nothing wired to its pill, an unbound pill, a pill pointing at an asset the build does not carry, a variable no level of the chain declares any more, or a variable whose type changed since the node was made all read the type default and warn once per node, and refuse the write on the Set side rather than putting a zero over an authored value. A Set node whose value input is unwired is refused as well, for the same reason. The warnings re-arm on a game reset, so a problem that is still there is still reported after a restart
