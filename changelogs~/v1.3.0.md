##### New Features

- **Data Assets Arrive With the Project**: Import a StoryFlow Editor export containing `.sfd` Data Assets and the plugin creates assets for them, including parent relationships and referenced media. A child reads the closest value in its inheritance chain until it overrides that value. Assets can be found by stable ID or by a unique display name, so game code can use data that is not referenced by a dialogue node

- **Read and Write Data Assets in Dialogue**: Get Data Asset, Get Data Asset Variable and Set Data Asset Variable nodes bring authored data into value chains and story logic. A boolean Data Asset value can control whether an option appears. Array operations can change an asset's array during play, and writes live in session state rather than altering the imported asset

- **A Data Asset API for Game Code**: `StoryFlowManager` and `StoryFlowComponent` provide typed getters and setters for bool, int, float, string and enum values. `FindDataAsset` locates an asset, `GetDataAssetVariableNames` lists its declared variables and `GetDataAssetVariant` reads arrays and maps. Container setters can replace a declared array or map, with type checks before a write is accepted. These methods work outside an active dialogue too

- **Data Asset Changes Survive Save and Load**: Save slots and `ExportState` include values changed during the current session. Loading a save restores those changes, while a reset returns to the imported values. The state format also carries global, script and character state through one save path. Saves from earlier Unity plugin versions still load; saves written by this version cannot be read by an older plugin

- **Stable Character IDs**: Current StoryFlow Editor exports include a character index, and dialogue and character-variable nodes resolve characters by ID when one is available. `GetCharacterById`, `GetCharacterVariableById` and `SetCharacterVariableById` let game code keep a character binding when its file is renamed or moved. Older exports and path-based calls remain supported

- **Project-Wide Localization**: Import `localization.json` with the project to translate authored dialogue, character names and declared Data Asset strings. Use `StoryFlowManager.GetLanguages()` to build a language menu, `SetLanguage()` and `GetLanguage()` to change or read the selection and `OnLanguageChanged` to refresh your own UI. An unknown code is rejected without changing the current language. Runtime-written strings, Data Asset overrides and identifiers stay as authored

- **Audio-Driven Lip Sync**: Add `StoryFlowLipsync` to a character face and bind it to a StoryFlow dialogue component and character ID. It analyzes playing dialogue audio and drives existing ARKit-style mouth blendshapes without a per-line timing track or face-tracking hardware. The built-in poses support Synty Sidekick faces, including modular faces under a shared Face Root. A `StoryFlowVisemeMap` can map the poses to other blendshape names. Strength, sensitivity, jaw bias and smoothing can be tuned for the voice and rig, and a manual audio source can be supplied for playback outside the dialogue component

##### Improvements

- **Data Asset Values Stay Current After Sync**: Re-importing a project refreshes the values used by scripts and game code in the same session. The first import after upgrading may refresh existing StoryFlow assets once so they gain the new Data Asset and character data; later imports leave unchanged assets alone

- **Imported Media Resolves Across Scripts**: Image and audio values referenced by Data Assets are available from the project's shared media pool, even when the current dialogue script did not mention them

- **Lip Sync Follows the Actual Voice**: The face follows the active line's audio, keeps moving if that audio continues after dialogue text ends and returns to rest when playback stops. It also re-finds facial meshes that a character customization system replaces during play. `Level` and `RawPeak` readouts help tune quiet or loud recordings

- **Declared Variable Names Are Available to Nodes**: Get Data Asset Variable Names returns the names declared along an asset's parent chain, including inherited variables

##### Bug Fixes

- **Option Conditions From Multi-Output Nodes Work**: A condition wired to a particular output of Run Script or another node with several outputs now reads the connected output rather than an unrelated cached value

- **Character Names and Portraits Return After Loading**: A save that changed a character's built-in Name or Image now restores those fields along with its other variables

- **Data Asset Reads and Saves Keep Their Values**: Array and map reads return independent values, and writes or a save/load round trip no longer leave the runtime using an older copy of a Data Asset value

- **Localization Keeps Authored Text Separate**: Switching languages does not turn runtime values or identifiers into translation keys. Character display names follow the selected language when character records are refreshed, and language-change callbacks arrive in the correct order

##### Breaking Changes

- **Direct Save Helper Calls Need Data Asset Arguments**: Code that calls `StoryFlowSaveHelpers.Save` or `SaveAsync` directly must pass the Data Asset seed and current session values after the existing arguments. Calls through `StoryFlowManager.SaveToSlot` or `ExportState` are unchanged and provide those values automatically
